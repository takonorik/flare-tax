使い方

ウォレットを登録して取得 → 一覧を確認 → CSVをクリプタクトに取り込む、の流れです。

1. ウォレットを登録する

  • 名前とアドレスを登録します（最大20件、このブラウザに保存）。Flare Smart Accounts のアドレスも一緒に登録してください。
  • 登録したアドレスはすべて同じ持ち主として扱います。アドレス間の移動は送金として、CSVには出しません。
  • 「💾 ウォレットをファイルに保存」で、ウォレット・トークン設定・アドレス帳を別のブラウザやPCに引っ越せます。

2. 取引を取得する

  • 開始日・終了日はCSVに出す期間の絞り込みです。計算は常に全履歴が対象です（LP・貸付の元本を過去の預入から計算するため。初回の取得は数分かかります）。
  • 取得するのは公開されている取引履歴だけです。秘密鍵や署名は使いません。
  • 2回目からは、履歴ファイルを使うと数秒〜数十秒で終わります（下の手順）。

履歴ファイルの使い方（2回目から速くする）

取得した履歴をファイルに保存しておくと、次回は新しい取引だけを取りに行きます。計算はこれまでどおり全履歴で行うので、結果は変わりません。

  1. 初回は、そのまま取得：何も読み込まずに「取引を取得する」を押します（全履歴の取得なので数分かかります）。
  2. 保存する：終わると集計の上に帯が出ます。「💾 最新の履歴ファイルを保存」を押して、flare_history_年月日.json.gz を PC に保存します。
  3. 次回は、読み込んでから取得：「📂 履歴ファイルを読み込む」で保存したファイルを選び、「取引を取得する」を押します。
  4. また保存する：取得が終わったら、もう一度「💾 最新の履歴ファイルを保存」を押します。次回はこの新しいファイルを使います。
  • 読み込むと、予定が出ます：ファイル名の下に、ウォレットごとに「どこまで保存済みか」と「続きだけ取得するか、全履歴を取得するか」が出ます。履歴ファイルは、あればいつも読み込んでください（使えないファイルのときは、自動で全履歴を取得します）。
  • ファイルは常に1つです。登録した全ウォレットの分が1つに入ります。新しいファイルを保存したら、古いファイルは捨てて大丈夫です。
  • ウォレットを追加したときも、同じファイルを読み込んで取得します。追加したウォレットだけ全履歴を取り、同じファイルに入ります。
  • 全履歴を取り直す：ファイルを読み込むと出るチェックです。入れて取得すると、ファイルを使わずに最初から取り直します。申告の前などの節目や、ℹ️ の表示が出たときに使います。取り直したあとは、履歴ファイルとの違いも調べて、帯でお知らせします。
  • スマホで使う場合：履歴ファイルは使わず、何も読み込まずに取得してください（毎回、全履歴の取得になります）。ファイルの保存・読み込みと、クリプタクトへの CSV の取り込みは PC での利用を想定しています。

3. 一覧を確認する

  • 💴 の表示は、CSVで使う円価格です。「クリプタクトの時価で計算」はクリプタクトが持っている価格を使う行、「¥…/枚（自動）」はこのツールが付けた円価格です。

  • 🪙 トークン設定で、クリプタクトに無いトークン（カスタムコイン USER-…）か、対応コインかを選びます。
  • 📒 オープンポジション台帳で、LP・レンディングの残っている元本と、確定した損益を確認できます。

4. CSVをクリプタクトに取り込む

  • 「CSVダウンロード」で出したファイルを、クリプタクトにカスタムファイルとして取り込みます。
  • 1か月ずつ取り込むと、未分類取引（残高不足など）が出たときに原因を探しやすくなります。

前年までを別の方法で申告済みの場合

  • 今年の 1/1 00:00:00 に、前年末の残高を BUY（決済通貨 JPY、取得単価は前年の平均単価）で手入力します。前年の損益は変わりません。
  • 前年末に借りていたコインは、BUY ではなく BORROW（価格は空欄）で入れます。借りた分に取得価格が付かないようにするためです。
  • LP やレンディングに預けていた分も、クリプタクト上は手元にあるものとして残高に含めます（差分計上のため）。

未分類取引が出たとき

  • 保有枚数以上の売却：前年末の残高の入力漏れ、要確認の行の出し忘れ、LP報酬などの細かい端数がよくある原因です。端数ならクリプタクトの解消ウィザードで取得単価を入れて追加できます。
  • 借入枚数以上の返却：完済したあとに残っていた利息だけを返した行は、LOSS（利息）にします。このツールは自動で LOSS にして出力します。

取得漏れのチェック（ℹ️ の表示）

  • 取得のたびに、履歴から計算した FLR の残高と実際の残高を比べます。1 FLR 以上ずれていると、画面の上に ℹ️ で知らせます。
  • 計算のほうが少ない：エクスプローラー側のデータに欠けがあり、FLR の受け取りが一部出ていない可能性があります。エクスプローラーで最近の入金を確かめてください。
  • 計算のほうが多い：P チェーンへの移動（ステーキング）のように、エクスプローラーに出ない出金があるとこうなります。自分の資産の置き場所が変わっただけなら、損益には影響しません。

区分けの考え方

損益が生まれる行だけを出す。資産の置き場所が変わるだけの操作は出さない。

基本の扱い

取引CSVでの扱い考え方
SwapSELL（渡したコイン → 受け取ったコイン）コイン同士の交換は、売却として損益が出ます。クリプタクトに価格の無いコイン（カスタムコインや sFLR など）を受け取る交換は、受け取ったコインの BUY（支払いは渡したコイン）と書きます。意味は同じ交換です。
Wrap / Unwrap（FLR ⇔ WFLR）出力しない同じコインとして扱います。
リキッドステーキング（sFLR・stFLR・stXRP・flrETH）BUY / SELL（Swap）別のコインへの交換として扱います。ステークは受け取った LST の BUY、アンステークは渡した LST の SELL です。申請してから後日受け取るアンステークは、受取量が決まる時点で Swap にします（stFLR は申請時、sFLR は Unlock 後の受け取り時）。即時アンステークの手数料は受取量に含まれるので、別の行にはしません。
報酬（FTSO デリゲート、FlareDrop、各 dApp の報酬請求）BONUS受け取った時点の時価で所得になります。rFLR は WFLR に変換した時点で BONUS。自動クレーム（エグゼキューターが代わりに請求）も、届いた WFLR を BONUS にします。
自動クレームの設定（エグゼキューターの登録料）DEFIFEE登録のときに払う FLR は戻らないので経費です。
LP・レンディング・Vault への預け入れ差分計上（下で説明）預けただけでは損益は出ません。
借入BORROW / RETURN借入額を超えて返した分は利息として LOSS。
外部アドレスとの送受金要確認自分の別ウォレットなら送金（出力しない）、それ以外なら売買や受け取りとして種類を選びます。
ブリッジ手数料は SENDFEE、本体は要確認送り先が自分なら、本体は出力不要です。送った分がそのまま自分のアドレスに戻ってきた往復（例：USDT を Arbitrum 経由で USDT0 にして戻す）は自動で見つけて、同じトークンなら出力せず減った分だけ手数料、別のトークンなら Swap として出します。
ガス代行の手数料（FLR）出力する行の手数料として付けます。

差分計上（LP・レンディング・Vault）

預けている間の値動きは追わず、実際に手元に戻ったときに損益を確定させます。

  1. 預けたとき：LEND（CSVに出さない）。クリプタクト上はコインを持ったままです。
  2. 引き出したとき：元本までは RECOVER（出さない）。元本を超えて戻った分だけ BONUS（差益）。
  3. 完全に引き上げたとき：戻らなかった元本を LOSS（差損）。
種類「完全に引き上げた」の判定
V2 の LP（BlazeSwap・Enosys V2 など）受け取った LP トークンが0に戻ったとき
V3 の LP（SparkDEX・Enosys V3 など）ポジション（NFT）ごとに元本を管理し、そのポジションの流動性が0になったとき
レンディング・Vault預けた証明のトークン（kToken・シェアなど）が0に戻ったとき
  • 一部だけ引き出した場合は、先に元本に充てます（元本回収法）。途中の状態は「オープンポジション台帳」で確認できます。
  • LP は2種類のコインを預けるので、トークンごとに差益・差損を計算します。比率が変わるため、片方だけ差益が出たり、片方が差益でもう片方が差損になったりします。

FAssets（FXRP）と Flare Smart Accounts

  • FXRP は XRP と同じコインとして扱います（CSVでは XRP、価格はクリプタクトの時価）。
  • XRP → FXRP のミントと、FXRP → XRP の償還は、同じコインの移動なので出力しません。
  • 同じ考え方で、Flare の WETH（Stargate でブリッジした ETH）は ETH として出力します。flrETH は ETH とは別のコイン（カスタム USER-FLRETH）で、WETH ⇔ flrETH は交換です。
  • ミント予約手数料・償還のエグゼキューター手数料（FLR）は DEFIFEE（経費）。
  • FAssets の担保プールは差分計上で、手数料の分配（FXRP）は BONUS（XRP）。

XRPL Tax for Cryptact との役割分担

内容Flare Tax（このツール）XRPL Tax for Cryptact
Upshift などで増えた分引き出した時点で BONUS（XRP）記録しない
ミント・償還出力しない記録しない
Smart Account のミント・償還手数料出力しないDEFIFEE（XRP）

Smart Account の利益も Flare 側で計上します。Vault から引き出したあとも FXRP は Smart Account に残り、XRPL への償還は別の操作・ロット単位で端数が Flare に残るため、XRPL 側の「戻ってきた XRP − 送った XRP」では正しく計算できないからです。両方のツールで同じものを二重に出さないように分けています。

円価格の付け方

  1. クリプタクトに価格があるコインは、価格欄を空欄にしてクリプタクトの時価を使います。
  2. 価格の無いトークンは、このツールが円価格を付けます：決済通貨にできるコインとの交換レート → 同じ取引で経由した量 → 直前のプール価格 → 払い戻し比率、の順で探し、円へは bitbank の価格で換算します。
  3. クリプタクトに無いトークンは、カスタムコイン USER-… として出力します。

Cyclo（cysFLR）や Spectra（PT）などは Swap として出していますが、税務上の扱いが定まっていない取引です。ご自身で判断してください。

コメントの区分け一覧

一覧のコメント欄に出る [大項目] 中項目 の意味です。{トークン} {DEX} などには実際の名前が入ります。「CSV」は出力される種類と、既定の扱い（出力・スキップ・要確認）です。

コメントの末尾に付く語：差益＝元本を超えて戻った分（BONUS）、差損＝戻らなかった元本（LOSS）、利息＝借入額を超えて返した分（LOSS）、（自分のアドレス間）＝登録ウォレット同士の移動（スキップ）。
