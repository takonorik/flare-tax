# Flare Tax for Cryptact

Flare Network のウォレットの取引履歴を読み、日本の暗号資産の損益計算サービス「クリプタクト」に取り込める CSV を作るツールです。

- ウォレットのアドレスを登録するだけで、公開されている取引履歴を取得します。
- スワップ、LP、レンディング、リキッドステーキング、報酬などを、損益の出るものと出ないものに自動で分けます。
- 判断できない取引は「要確認」として一覧に出し、自分で種類を選べます。
- 円価格は、クリプタクトに価格があるコインはクリプタクトの時価、無いコインはこのツールが付けます。
- ブラウザだけで動きます。インストールは不要です。

## 使い方

1. https://takonorik.github.io/flare-tax/ を開きます（限定公開中は、アクセスコードの入力が必要です）。
2. ウォレットの名前とアドレスを登録します。Flare Smart Accounts のアドレスも一緒に登録してください。
3. 「取引を取得する」を押します。初回は全履歴を取るので数分かかります。
4. 一覧で内容を確認します。「要確認」の行は、自分で種類を選ぶか、出力しないかを決めます。
5. 「CSVダウンロード」で出したファイルを、クリプタクトにカスタムファイルとして取り込みます。

詳しい手順と、区分けの考え方は、画面の「使い方」「区分けの考え方」のページを読んでください。

## 履歴ファイル（2回目から速くする）

取得した履歴をファイルに保存しておくと、次回は新しい取引だけを取りに行きます。計算は毎回、全履歴で行うので、結果は全履歴を取り直したときと同じです。

1. 初回は、何も読み込まずに取得します。
2. 終わったら「最新の履歴ファイルを保存」を押します。`flare_history_年月日.json.gz` が保存されます。
3. 次回は「履歴ファイルを読み込む」で、そのファイルを選んでから取得します。
4. 取得が終わったら、もう一度「最新の履歴ファイルを保存」を押します。

ファイルは常に1つです。登録した全ウォレットの分が1つに入ります。新しいファイルを保存したら、古いファイルは捨てて構いません。

ファイルにはウォレットのアドレスと取引履歴が入っています。人に渡したり、公開したりしないでください。

## データの扱い

- このツールにサーバーはありません。アドレスや履歴が、このツールの運営者に送られることはありません。
- 計算は、お使いのブラウザの中で行います（Python をブラウザ内で動かす Pyodide を使っています）。
- 通信先は次のとおりです。
  - Flare のエクスプローラー（Blockscout）と、Flare の RPC：取引履歴の取得
  - bitbank：円価格の取得
  - jsDelivr：Pyodide の配布
- 登録したウォレット・トークン設定・アドレス帳は、お使いのブラウザ（localStorage）にだけ保存されます。
- 履歴ファイルと CSV は、お使いの端末にだけ保存されます。
- 使うのは公開されている取引履歴だけです。秘密鍵やシードフレーズは要りません。署名や送金もしません。

## 対応サービス

LP・レンディング・Vault の税務方針は「差分計上」です。預け入れは LEND、引き出しは RECOVER で元本を動かし、元本を超えて戻った分だけ BONUS（差益）にします。完全に引き上げたときの元本割れは、LOSS（差損）を自動で作ります。

「完全に引き上げた」の判定は次のとおりです。

- V2 の LP：受け取った LP トークンが0に戻ったとき
- V3 の LP：ポジション（NFT）ごとに元本を管理し、そのポジションの流動性が0になったとき
- レンディング・Vault：預けた証明のトークンが0に戻ったとき

一部だけ引き出した場合は、先に元本に充てます（元本回収法）。途中の状態でも計算は決まった結果になり、プール別の残りの元本と確定した損益は、画面の「オープンポジション台帳」で確認できます。

### Flare 本体の機能

| 機能 | 扱い |
|------|------|
| FLR・ERC-20 の送受金 | BUY / SELL（資金移動かどうか判断できないので要確認） |
| Wrap / Unwrap（FLR ⇔ WFLR） | 同じコインとして扱い、スキップ |
| FTSO デリゲート / FIP 投票 | ガス代のみ |
| 自動クレームの設定（ClaimSetupManager） | エグゼキューターの登録料を DEFIFEE（経費） |
| デリゲート報酬 / FlareDrop / FTSO 報酬の請求 / P-chain ステーキング報酬 | BONUS |
| rFLR | 受け取りはスキップ、WFLR に変換した時点で BONUS |
| FAssets（FXRP）のミント・償還 | XRP と同じコインなのでスキップ |
| FAssets のミント予約手数料 / 償還のエグゼキューター手数料 | DEFIFEE（経費） |
| FAssets の担保プール（預け入れ・引き出し、FCPT） | 差分計上。手数料の分配は BONUS |
| Flare Smart Accounts | ミント・償還はスキップ。Vault で増えた分は引き出し時に BONUS |
| 失敗した取引 | ガス代のみ。資産の移動なし |
| 他の人の取引の中で届いた FLR | 報酬コントラクトからの自動クレームは BONUS、それ以外は要確認（売却代金・送金の可能性） |
| 通過しただけのトークン | 同じ取引の中で同じ量が入って出た分（報酬の引換券など）は判定から外す |

| dApp | 対応内容 |

| BlazeSwap | Swap / V2 LP / デリゲート報酬の請求 |
| Enosys DEX | Swap / V2 LP（addLiquidityFLR の内部 FLR 返却に対応）/ ファームへの預け入れ |
| Enosys Loans | Trove の開閉（BORROW / RETURN と担保）/ Stability Pool / CDP の借入 |
| Kinetic | Supply / Withdraw / Borrow / Repay（LEND / RECOVER / BORROW / RETURN） |
| Mystic（Morpho） | Supply / Withdraw / Borrow（VaultV2 / Morpho） |
| sFLR / stFLR / stXRP / flrETH（リキッドステーキング） | ステークとアンステークを別のコインへの交換（Swap）として扱う。即時アンステークの手数料は受取量に含まれるので、別の行にしない。遅延アンステークは、受取量が決まる時点で Swap（stFLR は申請時、sFLR は Unlock 後の受け取り時。sFLR の数量は Redeem イベントから取得） |
| SPRK（xSPRK） | 変換とステーキングはスキップ、報酬は BONUS、早く戻したときのペナルティは LOSS |
| Kii（JOULE） | JOULE と同じコインとして扱う。報酬は BONUS |
| DaoFlare | DFLR の焼却はスキップ、HLN 報酬は BONUS |
| Upshift（earnXRP）/ MXRPY / More Markets | Vault の預け入れを差分計上 |
| Stargate / OFT ブリッジ | 手数料は SENDFEE。送付の本体は要確認（自分宛てなら出力不要）。同じトークンで戻った往復は、減った分だけ SENDFEE |
| Spectra（PT） | 固定利回りの預け入れ・引き出しは差分計上。原資産から IBT への変換は Swap |
| Cyclo（cysFLR） | Swap として出力（税務上の扱いは定まっていないので、ご自身で判断してください） |
| OpenOcean / UniversalRouter | 汎用の Swap 判定でカバー |

どの取引がどの区分けになるかの全一覧は、画面の「区分けの考え方」のページにあります。

### 取得漏れのチェック

取得のたびに、履歴から計算した FLR の残高と実際の残高を比べます。1 FLR 以上ずれていると、画面に ℹ️ で知らせます。エクスプローラーの内部トランザクションには欠けがあることがあり、P チェーンへの移動はエクスプローラーに出ないためです。

## 開発者向け

### 仕組み

画面（`index.html`）と、計算を動かす Worker（`web/worker.js`）、ブラウザ内の Python（Pyodide）、計算の本体（`flare_tax/`）でできています。Pyodide の中では、通信用の `httpx` を `web/httpx.py` で置き換えています。静的ファイルだけで動くので、GitHub Pages にそのまま置けます。

`main.py`（FastAPI）は、開発・テスト用に残してある API サーバーです。使う人は使いません。

`.nojekyll` は削除しないでください。GitHub Pages は既定で `_` から始まるファイルを配らないため、これが無いと `flare_tax/__init__.py` が取れなくなります。

### 手元で動かす

`start.command`（Mac）か `start.bat`（Windows）をダブルクリックします。次のように手で起動してもかまいません。

```bash
python3 -m http.server 5500
```

`http://localhost:5500` を開きます。`index.html` を直接開く（`file://`）と動きません。

### 公開と限定公開

main に push すると、GitHub Actions（`.github/workflows/deploy.yml`）が `scripts/build_site.py` で公開用のファイルをまとめ、GitHub Pages に公開します。Actions タブの「Run workflow」でも公開し直せます。

限定公開（アクセスコードの入力）は、GitHub の設定だけで切り替えます。`Settings → Secrets and variables → Actions` で:

| 設定 | 種類 | 値 |
|---|---|---|
| `ACCESS_CODE` | Secrets | アクセスコード（全角・大文字・前後の空白は区別しない） |
| `ACCESS_GATE` | Variables | `on`（コードが必要） / `off`（誰でも開ける） |

変えたあとは、Actions → Deploy → Run workflow で反映します。一度コードを入れた端末は記憶されます。コードを変えると、全員に入力し直してもらうことになります。

鍵がオンの間は、検索エンジンに載らないよう `noindex` を付けています。

### テスト

```bash
pip install -r requirements.txt
pytest
```

通信はしません。分類の「税務的な正しさ」を保証するものではなく、変更で出力が意図せず変わっていないかを見つける網です。

スナップショット系のテストは、自分のウォレットの履歴を録って使います。公開しているリポジトリには、個人の履歴を入れていません。録ったデータが無いと、そのテストはスキップされます。

```bash
# 自分のウォレットの履歴を録る (ネットワークを使う。tests/fixtures/ に保存される)
python tests/record_fixtures.py <ウォレットアドレス>

# 出力を意図的に変えたときのスナップショット更新
UPDATE_SNAPSHOTS=1 pytest
```

`tests/fixtures/` と `tests/snapshots/` は `.gitignore` に入っています。コミットしないでください。

### コード構成

```
index.html               — 画面（取得・一覧・CSV 出力・説明ページ）
web/
  worker.js              — Pyodide を動かす Worker
  httpx.py               — ブラウザ内で httpx の代わりをする通信部分
flare_tax/
  service.py             — 取得から結果までの流れ
  history.py             — 履歴ファイル（保存・読み込み・続きの取得）
  blockscout.py          — Blockscout API クライアント（全フェッチャは truncated フラグ付き）
  helpers.py             — 数量フォーマット（Decimal）/ 時刻変換 / 日付フィルタ
  classify.py            — 1件単位の基本分類（FLR の取引と ERC-20 転送の重複排除・合算）
  protocols.py           — プロトコル定義とハンドラのレジストリ（サービスの追加はここ）
  postprocess.py         — 取引ハッシュ単位のグループ後処理（汎用パターン推定 / ガス集約）
  pricing.py             — 円価格の取得と付与
  pipeline.py            — 取得済みデータから行を作る純粋なパイプライン
main.py                  — 開発・テスト用の FastAPI（薄い API 層）
tests/                   — テスト
```

### 新しいサービスの足し方

`flare_tax/protocols.py` に matcher と handler を書き、`PROTOCOL_HANDLERS` に登録します。既存のロジックには触れません。区分けを増やしたら、`index.html` の「区分けの考え方」のページも合わせて直してください。
